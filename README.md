# Вакансии hh.ru: три вопроса к рынку

[![CI](https://github.com/MeldanLess/vacancy-dashboard/actions/workflows/ci.yml/badge.svg)](https://github.com/MeldanLess/vacancy-dashboard/actions/workflows/ci.yml)
[![Python 3.12](https://img.shields.io/badge/python-3.12-3776ab.svg)](https://www.python.org/downloads/)
[![Лицензия: MIT](https://img.shields.io/badge/лицензия-MIT-0f7b4f.svg)](LICENSE)

Проект разбирает выгрузку вакансий с открытого API hh.ru и отвечает на три
вопроса о рынке ИТ-работы в России:

1. **Какие технологии просят чаще всего** и как их доля меняется по месяцам.
2. **Где платят больше** — по группам городов, от Москвы до регионов.
3. **Сколько стоит опыт** — какая разница между junior, middle и senior и как
   с уровнем связана удалённая работа.

Главное правило проекта: **число, которое нельзя проверить, не публикуется**.
Каждый график подписан числом вакансий, на которых он построен, каждая
медиана — размером группы, а каждое ограничение данных названо прямо, а не
спрятано в сноску.

## Как устроено

```
hh.ru API  →  collect.py  →  clean.py  →  features.py  →  analysis.py  →  графики, таблицы, тексты
             (сырой JSON)   (таблица)    (признаки)      (три ответа)
```

| Модуль | Что делает |
|---|---|
| `config.py` | Словарь технологий и правила разбора: какие написания относятся к какой технологии |
| `collect.py` | Постраничный сбор с hh.ru: паузы, повторы, учёт `Retry-After` при 429 |
| `clean.py` | Таблица вакансий: дубликаты, архивные, зарплаты «на руки», месяцы |
| `features.py` | Признаки из текста: технологии, уровень должности, город, формат работы |
| `analysis.py` | Три вопроса: таблица, текст-ответ и график к каждому |
| `charts.py` | Оформление графиков: палитра, подписи, оси |
| `pipeline.py` | Сквозной прогон: JSON → таблица → ответы → файлы |
| `app/dashboard.py` | Дашборд на Streamlit: те же ответы с фильтрами |

## Как запустить

```bash
# 1. Зависимости
pip install -r requirements.txt -r requirements-dev.txt

# 2. Собрать вакансии с hh.ru (нужна сеть)
python -m vacancy_dashboard.collect --text python --pages 20

# 3. Посчитать ответы и построить графики
python -m vacancy_dashboard.pipeline --input data/raw/vacancies.json

# 4. Посмотреть на то же самое с фильтрами
streamlit run app/dashboard.py
```

Токен hh.ru не обязателен: без него API отдаёт меньше результатов, но
работает. Если он есть, положите его в переменную окружения `HH_TOKEN`, а
`User-Agent` — в `HH_USER_AGENT` (имя приложения и почта для связи — условие
работы API, а не формальность).

Есть и `make`: `make install`, `make test`, `make collect`, `make pipeline`,
`make app`.

### Тесты и ноутбуки

```bash
pytest --cov=vacancy_dashboard --cov-report=term-missing
ruff check . && ruff format --check .

# Пересобрать ноутбуки из скрипта
python scripts/build_notebooks.py

# Выполнить ноутбуки
jupyter nbconvert --to notebook --execute notebooks/01_stack.ipynb
```

Ноутбуки лежат в `notebooks/` и собираются скриптом: код в них не расходится
с кодом пайплайна, а в репозитории лежит один источник правды. Тест сверяет
каждый ноутбук с тем, что собирает скрипт, — расхождение видно сразу, а не
только в CI.

## Что в проекте честно

Этот раздел важнее любого графика: именно здесь видно, чему в данных
доверять нельзя.

**Зарплата «от» — это нижняя граница, а не зарплата.** Работодатель пишет
«от 150 000 ₽», чтобы набрать больше откликов. Медиана нижних границ
занижена относительно медианы фактических предложений, и никакая обработка
это не исправит. Все зарплаты в проекте — нижние границы вилок, и это
написано на графиках.

**«Грязные» и «чистые» зарплаты — разные числа.** hh.ru честно помечает,
указана ли сумма до или после вычета налога. Всё приводится к сумме «на
руки»: «до вычета» делится на 1,13. Это допущение, а не факт.

**Вакансии без зарплаты — не нулевые.** Их нельзя выбрасывать молча: сколько
их было, показывается рядом с каждым подсчётом.

**Стек и уровень должности разбираются из текста.** В hh.ru нет полей «стек»
и «уровень», поэтому технологии ищутся по требованиям и обязанностям
регулярными выражениями, а уровень — по названию должности. Способ честный,
но шумный: он спотыкается о «Python-разработчик в компании, где есть Go» и
о вакансии, где уровень не назван. Доля вакансий, где признак удалось
определить, показывается рядом с каждым графиком.

**Маленькие группы показываются как маленькие.** В группах, где меньше 30
наблюдений, медиана — это шум, а не характеристика рынка. Такие группы
помечаются прямо в тексте ответа.

**Одна выгрузка — один момент времени.** API hh.ru отдаёт вакансии на
момент запроса; архивные убираются, но «срез рынка» не восстанавливается
задним числом.

## Результаты

> **Раздел ждёт настоящей выгрузки.** Числа ниже появятся после первого
> сбора с hh.ru. До этого в репозитории лежит только синтетическая фикстура
> `tests/fixtures/vacancies_sample.json` — она нужна для тестов, и её числа
> **нельзя** выдавать за рыночные.

Когда выгрузка собрана, сюда попадает:

- дата и параметры сбора (поисковый запрос, число страниц, период);
- размер выборки и сколько вакансий осталось без зарплаты;
- ответы на три вопроса — текстом и графиками из `docs/figures/`;
- оговорки, которые сработали именно на этих данных.

Заполняется это одним прогоном:

```bash
python -m vacancy_dashboard.collect --text python --pages 20
python -m vacancy_dashboard.pipeline --input data/raw/vacancies.json
```

Пайплайн печатает сводку и тексты трёх ответов — их можно скопировать сюда
дословно, вместе с числом вакансий, на которых они посчитаны.

## Структура репозитория

```
vacancy-dashboard/
├── vacancy_dashboard/        # пакет: сбор, очистка, признаки, ответы, графики
├── app/dashboard.py          # дашборд на Streamlit
├── notebooks/                # три ноутбука — по одному на вопрос
├── scripts/build_notebooks.py # сборка ноутбуков из кода
├── tests/                    # тесты и синтетическая фикстура
├── data/                     # сырые и обработанные данные (не в репозитории)
├── docs/figures/             # графики (не в репозитории)
└── .github/workflows/ci.yml  # стиль, тесты, ноутбуки
```
